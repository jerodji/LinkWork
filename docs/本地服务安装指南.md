# LinkWork 本地服务安装指南

本文介绍如何在自己的电脑上安装并运行 LinkWork 的本地服务。

LinkWork 由两部分组成：

| 部分 | 作用 |
| --- | --- |
| 浏览器扩展 | 提供侧边栏界面，读取页面数据，显示与复制文案 |
| 本地 Python 服务 | 下载媒体、语音识别、图片 OCR、文案整理与校准 |

只安装浏览器扩展、不安装本地服务时，扩展会显示「服务未连接」，无法提取文案。

---

## 1. 环境要求

当前安装脚本主要面向 **macOS**。

| 项目 | 要求 |
| --- | --- |
| 系统 | macOS |
| 浏览器 | Edge 或 Chrome 114 及以上 |
| Python | 3.10 – 3.13，且包含 tkinter |
| ffmpeg | 安装脚本会自动处理（通过 imageio-ffmpeg） |
| 磁盘 | 首次安装约 1–3 GB（含语音识别模型） |

如果本机没有合适的 Python，建议先安装 `uv`，它会自动下载合适的 Python：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

安装后请新开一个终端窗口，让 `uv` 进入 `PATH`。

---

## 2. 获取项目

从 GitHub 下载或克隆项目：

```bash
git clone https://github.com/jerodji/LinkWork.git
cd LinkWork
```

也可以直接在 GitHub 页面点 **Code → Download ZIP**，解压后进入项目目录。

下文所有命令都假设终端当前位于项目根目录。

---

## 3. 推荐安装方式：一键脚本

在项目目录运行：

```bash
./scripts/install_linkwork.sh
```

脚本会依次完成：

1. 创建隔离的 Python 虚拟环境 `.venv`
2. 安装项目依赖（含 faster-whisper、网页正文解析、Apple 语音识别）
3. 编译并注册「本机启动器」（native messaging host）
4. 提示你在浏览器中加载扩展

脚本结束后，按终端提示完成最后一步：

1. 打开扩展管理页
   - Edge：`edge://extensions/`
   - Chrome：`chrome://extensions/`
2. 打开右上角的 **开发人员模式**
3. 点 **加载解压缩的扩展**
4. 选择项目中的 `extension` 目录

例如：

```text
/Users/你的用户名/LinkWork/extension
```

5. 完全退出浏览器（`Command + Q`），再重新打开

之后点击工具栏的 LinkWork 图标，右侧面板打开时会自动启动本地服务。右上角显示绿色「连接已开启」即表示服务正常。

---

## 4. 手动安装方式

如果不使用一键脚本，可以按下面步骤手动安装。

### 4.1 安装 Python 依赖

```bash
./scripts/setup.sh
```

该脚本会创建 `.venv` 并安装依赖。完成后可以运行环境自检：

```bash
.venv/bin/python -m linkwork doctor
```

自检会检查 ffmpeg、yt-dlp、语音识别引擎和图片 OCR 是否可用。

### 4.2 注册本机启动器

```bash
.venv/bin/python scripts/install_native_host.py
```

只注册某一个浏览器时：

```bash
.venv/bin/python scripts/install_native_host.py edge
.venv/bin/python scripts/install_native_host.py chrome
```

注册后必须完全退出并重新打开浏览器，注册信息才会生效。

### 4.3 启动本地服务

手动启动：

```bash
./scripts/service.sh start
```

后台运行，日志写入：

```text
~/Library/Logs/LinkWork-service.log
```

### 4.4 加载浏览器扩展

打开 `edge://extensions/` 或 `chrome://extensions/`，开启开发人员模式，选择「加载解压缩的扩展」，选中项目中的 `extension` 目录。

---

## 5. 验证安装

### 5.1 检查服务状态

```bash
./scripts/service.sh status
```

正常时应显示服务正在运行，并返回健康检查 JSON。

### 5.2 手动检查健康接口

```bash
curl http://127.0.0.1:17890/api/health
```

正常返回类似：

```json
{
  "ok": true,
  "name": "linkwork",
  "version": "0.2.27",
  "ffmpeg": true,
  "asr": [
    {"name": "faster-whisper", "available": true}
  ]
}
```

### 5.3 检查扩展连接

打开浏览器侧边栏，右上角应显示：

- 绿色圆点
- 「连接已开启」

如果显示「服务未连接」，先确认服务正在运行，然后点状态灯重新连接。

## 6. 日常使用

| 操作 | 命令 |
| --- | --- |
| 启动服务 | `./scripts/service.sh start` |
| 停止服务 | `./scripts/service.sh stop` |
| 查看状态 | `./scripts/service.sh status` |
| 重启服务 | `./scripts/service.sh restart` |
| 前台运行（调试） | `./scripts/service.sh foreground` |

默认端口是 `17890`。需要换端口时：

```bash
LINKWORK_PORT=17891 ./scripts/service.sh start
```

或前台运行：

```bash
.venv/bin/python -m linkwork serve --port 17891
```

更新代码后，需要重启服务：

```bash
git pull
./scripts/setup.sh        # 仅当依赖有变化时需要
./scripts/service.sh restart
```

## 7. 命令行用法（可选）

不打开浏览器也可以直接用命令行提取：

```bash
.venv/bin/linkwork "https://www.bilibili.com/video/BV1xx411c7mD"
```

常用参数：

```bash
# 指定输出目录和格式
.venv/bin/linkwork -o ./output --format md,txt,json "链接"

# 只提取平台字幕，不做语音识别
.venv/bin/linkwork --subtitles-only "链接"

# 使用本机 Chrome 的登录 Cookie
.venv/bin/linkwork --cookies browser:chrome "链接"

# 关闭文案校准
.venv/bin/linkwork --no-calibrate "链接"
```

更多参数：

```bash
.venv/bin/linkwork --help
```

## 8. 配置项

以下环境变量可以在启动服务或命令行时使用：

| 环境变量 | 说明 | 默认值 |
| --- | --- | --- |
| `LINKWORK_PORT` | `service.sh` 使用的端口 | `17890` |
| `LINKWORK_OUTPUT_DIR` | 命令行导出目录 | `./output` |
| `LINKWORK_CACHE_DIR` | 媒体缓存目录 | `~/Library/Caches/LinkWork/media` |
| `LINKWORK_WHISPER_MODEL` | Whisper 模型 | `small` |
| `LINKWORK_ZHIPU_API_KEY` | 智谱 API Key（文案校准） | 空 |
| `LINKWORK_LLM_MODEL` | 校准模型 | `glm-4.5-flash` |
| `LINKWORK_LLM_TIMEOUT` | 校准请求超时（秒） | `60` |

示例：

```bash
LINKWORK_ZHIPU_API_KEY="你的 Key" ./scripts/service.sh restart
```

浏览器扩展的设置页也可以单独填写 API Key，扩展会把 Key 随请求传给本地服务。

## 9. 日志与数据位置

| 位置 | 内容 |
| --- | --- |
| `~/Library/Logs/LinkWork-service.log` | 本地服务日志 |
| `~/Library/Logs/LinkWork-native-host.log` | 本机启动器日志 |
| `~/Library/Logs/LinkWork-service.pid` | 服务进程 PID |
| `~/Library/Caches/LinkWork/` | 下载的媒体与识别中间产物 |
| `~/Library/Caches/LinkWork/tasklogs/` | 单次任务诊断日志 |
| `<项目目录>/output/` | 命令行导出结果 |

媒体缓存会在任务结束后自动清理。异常中断留下的缓存可以在扩展设置页手动清除。

## 10. 常见问题

### 提示「未找到可用的 Python」

安装 `uv` 后重新运行安装脚本：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
./scripts/install_linkwork.sh
```

### 提示服务未连接

1. 检查服务是否运行：

   ```bash
   ./scripts/service.sh status
   ```

2. 如果未运行，启动：

   ```bash
   ./scripts/service.sh start
   ```

3. 如果端口被占用，换一个端口启动，并在扩展侧边栏重新连接。

### 首次识别很慢

首次使用 faster-whisper 会下载模型，体积较大。下载完成后会缓存到本机，后续速度会明显提升。

### 抖音 / 小红书提示需要登录

这两个平台未登录时通常不返回内容。请先在同一浏览器登录对应网站，再从详情页复制链接，用浏览器扩展重试。

### 文案校准提示「未配置智谱 API Key」

文案校准需要智谱 API Key。可以在扩展设置页填写，或设置环境变量：

```bash
export LINKWORK_ZHIPU_API_KEY="你的 Key"
./scripts/service.sh restart
```

不配置 Key 不影响提取，只会跳过校准并使用原文。

### 安装脚本报权限问题

确认脚本有执行权限：

```bash
chmod +x scripts/*.sh
```

## 11. 卸载

```bash
# 1. 停止服务
./scripts/service.sh stop

# 2. 删除浏览器注册文件（Edge）
rm -f ~/Library/Application\ Support/Microsoft\ Edge/NativeMessagingHosts/com.linkwork.host.json

# Chrome 则删除：
# ~/Library/Application Support/Google Chrome/NativeMessagingHosts/com.linkwork.host.json

# 3. 在浏览器扩展管理页移除 LinkWork

# 4. 删除项目目录与日志/缓存
rm -rf ~/Library/Logs/LinkWork-*.log
rm -rf ~/Library/Caches/LinkWork
```

---

## 12. 安全说明

- 本地服务只监听 `127.0.0.1`，默认不对局域网或公网开放。
- 音频和视频在本机完成识别，不上传到第三方服务。
- 只有开启文案校准后，提取出的文本才会发送给智谱 API。
- 智谱 API Key 保存在本机浏览器扩展存储或环境变量中，请勿提交到代码仓库。
